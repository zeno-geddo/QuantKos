QuantKos v0.1.0 (Beta)
QuantKos is a high-performance Monte Carlo option pricing engine written in modern C++20 and built on top of the Kokkos performance portability framework. It provides a single-source implementation capable of targeting serial execution, multi-core CPUs, and modern GPUs while maintaining the same code base.

4. Default Static Analysis Warnings

Enforces clean, robust code quality rules across GCC, Clang, and AppleClang.

Applies static checking flags to prevent common C++ bugs:

  • -Wall & -Wextra: Turns on standard and advanced compiler diagnostic warnings.
  • -Wpedantic: Rejects non-standard compiler-specific C++ extensions.
  • -Wshadow: Triggers warnings when local variables shadow outer scope declarations.
  • -Wnon-virtual-dtor: Flags classes with virtual methods that are missing virtual destructors.

3.5. Public Optimization Flags

Propagates critical performance assumptions to downstream consumers (app & tests).

Applies math optimization flags publicly to ensure identical compilation assumptions between our library objects and consuming binaries.

  • -fno-math-errno: Disables POSIX math 'errno' tracking, unleashing hardware vectorization (SIMD) and allowing seamless inlining across files during LTO.

6. Debug Mode Configurations

Optimization and runtime sanitization configurations for Debug targets.

Sets optimization to -O0 to preserve execution structure during step-by-step debugging.

Adaptive Debug Sanitizers (PUBLIC Propagation)

Conditionally configures compiler and linker instrumentation for sanitizers.

Host-side sanitizers (ASan/UBSan) are highly beneficial on CPU backends. However, on GPU-accelerated backends (CUDA/HIP/SYCL), ASan's massive virtual shadow memory allocation conflicts with the GPU driver's virtual memory mapping tables, triggering a critical initialization out-of-memory error. To prevent this, the build system queries the active Kokkos hardware configurations and automatically bypasses host sanitization if a GPU-bound accelerator target is active.

6. Production Release Optimization Configuration

Maximizes runtime execution performance:

  • -O3: Activates loop vectorization, automatic inlining, and registers.
  • -march=native: Inspects and exploits instruction sets (like AVX-512) native to the compilation host.
  • -flto: Link Time Optimization; performs cross-file optimizations across files.
  • -fno-math-errno: Bypasses updating POSIX error variables after math commands, enabling SIMD execution. (set before in the global optimizations)

6.5 Profiling Optimization Configuration

Maintains the exact performance optimizations of -O3 and LTO, but compiles in debug mapping coordinates (-g) and frame pointers to support profiling tools (e.g., perf, VTune, Valgrind).

Defines minimum build environment requirements and system language standards.

project_requirements

  • CMake Version: Require 3.20+.
  • Language Standard: Strict C++20 without compiler extensions.
    Note
    Compiler Portability Statement: This engine is written in standard-compliant C++20 with compiler extensions disabled (CMAKE_CXX_EXTENSIONS OFF).
    • Fully Tested & Verified: GCC (Version 11.2 and above).
    • Expected Compatible: Clang (Version 13+) and MSVC (2022+). While these toolchains conform to the standards used, they are currently untested.

build_type_configuration

@variable CMAKE_BUILD_TYPE

Specifies compiler optimizations. Defaults to "Release" (-O3) if left empty.

Valid build targets:

  • Release: Maximized execution speed with optimized compiler pipelines.
  • Debug: Full debugging symbols and no optimizations.
  • RelWithDebInfo: Release + active debugging symbols.

installation_prefix

Target Destination Setup, Configures where compiled libraries, binaries, and templates are saved.

Bypasses standard system directories in favor of a local directory named install/ at the project root. This ensures users can compile and deploy without administrator or sudo privileges.

build_options

User-Configurable Build Options. Use these toggles to customize the precision type, testing suite, and dependency download policies.

@option QKOS_ENABLE_SINGLE_PRECISION

Activates 32-bit single precision (float) calculations instead of 64-bit double precision.

Increases parallel memory bandwidth on GPU hardware, but reduces numeric precision.

@option QKOS_ENABLE_FAST_MATH

Enable aggressive non-IEEE fast-math optimizations

@option QKOS_ENABLE_CPU_OPT_REPORTS

Enable generating text files showing the inlining and vectorization performed

@option QKOS_ENABLE_TESTS

Directs CMake to compile the unit test suite and configure CTest execution.

@option QKOS_ENABLE_FETCHCONTENT

Allows the build system to automatically download and compile missing dependencies from GitHub.

@option QKOS_BUILD_DOCS

Generates HTML documentation using Doxygen during the build process.

dependency_resolution

External Dependencies Resolution. Employs a robust search-or-download hierarchy to obtain necessary parsing and execution frameworks.

yaml_cpp_subsec

Dependency: yaml-cpp. Library used to parse configuration files (.yaml).

Note
If missing locally and fetch mode is active, it pulls clean tag 0.8.0 from GitHub, turning off internal tests and tools to speed up overall compilation times.

kokkos_subsec

Dependency: Kokkos. Multi-threaded execution and performance portability model targeting CPU and GPU execution spaces.

Note
If missing locally and fetch mode is active, pulls stable tag 4.2.00 from GitHub.

src_sec

Source Library Tree Assembly. Traverses the src/ directory to build the core mathematical integration and model solvers.
