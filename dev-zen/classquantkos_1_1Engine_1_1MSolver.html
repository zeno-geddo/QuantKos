Detailed Description

template<KI::MathModel ModelPolicy, KI::NumScheme SchemePolicy, KI::OptType OptType, KI::OptRight OptRight>
class quantkos::Engine::MSolver< ModelPolicy, SchemePolicy, OptType, OptRight >

Host-side parallel launch coordinator and execution bridge.

  • Manages execution pipelines by grouping parameters, evaluating paths storage rules, and scheduling high-throughput integration kernels to the hardware backend.
    Note
    This class is instantiated once at the beginning of the MonteCarlo simulation, and the execute batch is called once for each batch.
    The integration kernel is created at the beginning of each batch, and it will be used by all threads during the simulations of the batch.
  • ### Host-Device Orchestration Lifecycle:
    [ HOST (CPU) SIDE ] [ DEVICE (GPU) SIDE ]
    * +----------------------------+
    | SDESolver |
    | (Orchestrates launch data) |

    |
    | Instantiates & Populates
    v
    +-----------------------------+ +-----------------------------+
    | IntegrationKernel | ------------> | Thread Lane 0: operator()(0) |
    | (A trivially copyable | Parallel | Thread Lane 1: operator()(1) |
    | snapshot of state data) | Launch | Thread Lane 2: operator()(2) |
    +-----------------------------+ +-----------------------------+
  • Template Parameters
    ModelPolicyStochastic asset model to consider (e.g., Heston, Bates, etc.).
    SchemePolicyTime-stepping scheme to use (e.g., Euler, Milstein, AndersonQE, etc.).
    OptTypeOption contract payoff logic (e.g., European, Asian, Barrier, etc.).
    OptRightOption contract right (Call or Put).
    Todo:
    Should implement non-markovian models. This could be modified to work also with a non marlovian integration kernel.
